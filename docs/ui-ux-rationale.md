# UI/UX 통일 작업 — 무엇을, 왜 바꿨는가

색상 팔레트는 그대로 두었습니다(순수 `#ffffff` / `#000000` 바탕, 의미 색 4종, 프로젝트 색 10종 — `globals.css`의 색 토큰은 한 줄도 바꾸지 않았습니다). 바꾼 것은 **크기·모양·움직임·위계의 규칙**입니다.

## 1. 진단: 화면마다 "거의 같지만 조금씩 다른" 값

각 화면은 따로 보면 잘 다듬어져 있었지만, 화면을 넘나들 때 같은 역할의 요소가 미세하게 달랐습니다. 전체 CSS(27개 파일, 약 1만 8천 줄)를 집계한 결과입니다.

| 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 글자 크기 | 21종 (10.5, 11, 11.5, 12, 12.5, 13, 13.5, 14, 14.5 … ) | 10단계 토큰 |
| 글자 굵기 | 6종 (400, 450, 500, 550, 600, 700) | 4종 |
| 줄 간격 | 13종 (1.1 ~ 1.7) | 4종 (1 / 1.25 / 1.4 / 1.55) |
| 자간 | 11종 | 5종 |
| 모서리 반경 | 원시 px 값 12종이 토큰과 혼용 | 토큰 6단계 (1~3px 막대 끝 처리만 예외) |
| 전환·애니메이션 시간 | 31종 (0.1, 0.12, 0.14, 0.15, 0.16, 0.18 …) | 4단계 토큰 (루프·장식 애니메이션만 예외) |
| 패널 안쪽 여백 | 8가지 | 3단계 토큰 |
| 격자 밖 여백(3·5·7·9·11·18·22px) | 50곳 이상 | 의도된 정렬값만 남김 |
| 포커스 표시 | 6가지 변형 | 2가지 (규칙으로 구분) |
| 버튼 구현 | 공통 버튼 + 홈 화면 자체 구현 5종 | 공통 버튼 |

**근거:** 0.5px·0.02초 차이는 하나씩은 눈에 띄지 않지만, 사용자는 화면 전체에서 "정돈되지 않았다"는 인상으로 받아들입니다. 차이가 의도인지 실수인지 구분할 수 없는 값은 위계를 전달하지 못하므로, 차이를 낼 거면 한 단계 이상 분명하게, 아니면 같게 만드는 것이 원칙입니다.

## 2. 디자인 토큰 (`web/src/app/globals.css`)

### 글자 크기 — 10단계
`--fs-2xs` 11 · `xs` 12 · `sm` 13 · `base` 14 · `md` 15 · `lg` 16 · `xl` 18 · `2xl` 20 · `3xl` 30 · `display` 40

- 12.5px·13.5px 같은 반 픽셀 단계를 없앴습니다. **근거:** 반 픽셀은 비 Retina 화면에서 정수로 반올림되어 기기마다 다르게 보이고, 12와 12.5의 차이는 위계로 읽히지 않습니다.
- 스냅 방향은 역할로 정했습니다. 날짜·개수·설명 같은 메타 정보는 12, 버튼·사이드바 같은 조작 요소는 13, 읽는 본문과 작업 제목은 14.
- 입력창의 16px(모바일)은 유지했습니다. **근거:** iOS Safari는 16px 미만 입력창에 포커스하면 화면을 확대합니다.

### 굵기·줄 간격·자간
- 굵기는 400(본문) / 500(조작 요소) / 600(제목) / 700(페이지·섹션 제목). 450·550은 시스템 글꼴에 따라 지원되지 않아 기기마다 결과가 달랐습니다.
- 줄 간격은 1(한 줄 컨트롤) / 1.25(제목) / 1.4(UI 텍스트) / 1.55(문장). 한글은 받침과 획 때문에 영문보다 줄 간격이 넉넉해야 읽기 편해 문장용을 1.55로 통일했습니다.

### 모서리 반경 — 크기에 비례
`--radius-xs` 4(태그·배지) · `sm` 6(28px 이하 컨트롤, 목록 행) · 기본 8(32px 이상 컨트롤, 카드 안의 카드) · `lg` 12(카드·팝오버·다이얼로그) · `xl` 16(모바일 시트) · `full`(알약)

- **규칙:** 컨트롤 높이 28px 이하는 6px, 32px 이상은 8px. 변경 전에는 같은 28px 버튼이 화면에 따라 6px이기도 8px이기도 했습니다(사이드바·상단 바 아이콘 버튼 vs 공통 아이콘 버튼).
- 팝오버(12px, 안쪽 여백 6px) 안의 메뉴 항목을 8px → 6px로. **근거:** 안쪽 반경 = 바깥 반경 − 여백(12 − 6 = 6)일 때 모서리가 평행하게 보입니다(동심 반경).

### 움직임 — 4단계
`--dur-fast` 0.14s(호버·누름) · `--dur` 0.2s(메뉴·토글) · `--dur-mid` 0.32s(패널·레이아웃) · `--dur-slow` 0.5s(화면·블록 등장)

- **근거:** 반응은 빠르게(100~150ms 안쪽이어야 즉각적으로 느껴짐), 이동 거리가 큰 것일수록 길게. 같은 호버인데 0.1/0.12/0.15/0.16초로 제각각이면 앱이 미묘하게 불균일하게 느껴집니다.
- 지연(delay)과 반복 애니메이션(스피너, 펄스, 흐름 표시)은 건드리지 않았습니다. 완료 체크 애니메이션은 JS 타이머(380ms)보다 짧게 유지되는 것을 확인했습니다.

### 컨트롤 높이
`--control-xs` 24 · `sm` 28 · 기본 32 · `lg` 36 — 공통 버튼·입력창·아이콘 버튼·세그먼트가 이 토큰을 씁니다.

### 여백 — 격자와 패널 안쪽 여백
- **격자:** 16px 미만은 2px 단위(2·4·6·8·10·12·14), 16px 이상은 4px 단위(16·20·24·28·32·40·48…). 변경 전에는 안쪽 여백·간격에 3·5·7·9·11·18·22px이 50곳 넘게 섞여 있었습니다. **근거:** 격자 밖의 값은 옆 요소와 1px씩 어긋나게 만들고, 위계(가까운 것끼리 묶이고 먼 것끼리 나뉨)를 흐립니다.
- **패널 안쪽 여백 3단계:** `--inset-sm` 12/16(알림·안내 띠·파급 카드·Jev 패널) · `--inset` 16(요약 타일·홈 상태 알림) · `--inset-lg` 20(카드). 변경 전에는 `12px 14px`, `14px 16px`, `16px 16px 16px 18px`, `22px 20px` 등 8가지였습니다.
- **좌우는 항상 16px 이상:** 홈에서 위아래로 붙은 상태 알림(왼쪽 18px)과 Jev 안내(14px)의 아이콘이 4px 어긋나 있었습니다. 둘 다 16px로 맞춰 아이콘 시작점이 같은 세로선 위에 옵니다. **근거:** 쌓인 패널의 내용이 같은 선에서 시작해야 눈이 위아래로 자연스럽게 훑습니다.
- **작은 라벨(배지·개수·kbd·태그):** 좌우 6px, 아이콘과 글자 사이 4px. 버튼은 6px. 두 종류의 툴팁(CSS용·JS용)도 `6px 10px`로 같게 했습니다.
- **일부러 남긴 홀수 값:** 아이콘을 글자 줄 가운데에 맞추는 1~3px, 겹침용 −1px, 30px 정사각형 버튼 안에 16px 아이콘을 가운데 두는 7px, 실제 행 높이를 흉내 내는 스켈레톤의 11px(+테두리 1px), 앞 요소 위치에 맞춰 계산한 들여쓰기(21·26·30·34·38px).

## 3. 화면 간 통일

### 제목 위계를 한 벌로
| 단계 | 규격 | 쓰이는 곳 |
| --- | --- | --- |
| 페이지 제목 | 40 / 700 (모바일 30) | 모든 화면 |
| 페이지 섹션 | 20 / 700 (`ui.pageSection`) | 홈 "지연 파급·급한 업무", 파급 예측 "지금 밀리고 있는 일정·핵심 작업" |
| 블록·카드 제목 | 15 / 600 | 설정 카드, 빈 상태 |
| 목록 그룹 | 14 / 600 | 오늘·예정·전체 작업의 그룹 머리글 |

- 변경 전: 같은 수준의 섹션이 홈에서는 22px/700, 파급 예측에서는 15px/600이었습니다. **근거:** 같은 깊이의 정보는 같은 모양이어야 사용자가 화면 구조를 한 번만 학습하면 됩니다.
- 섹션 사이 간격(홈 44px / 파급 예측 40px)과 제목 아래 간격(18 / 14px)도 40px / 16px로 맞췄습니다.

### 버튼
- 홈의 자체 구현 버튼(`btnPrimary`, `btnGhost`, `dbTool`, `dbNew`, `dbChip`)을 공통 버튼으로 교체했습니다. 높이·반경·글자 크기·포커스·누름 반응이 다른 화면과 동일해졌고 CSS 약 100줄이 줄었습니다.
- 홈 보드의 "새 작업"·"새 일정"을 채워진 버튼에서 **윤곽선 버튼**으로. **근거:** 변경 전 홈에는 검은 주 버튼이 3개(재조정, 새 작업, 새 일정) 동시에 보였습니다. 한 화면에 주 버튼은 하나여야 "지금 가장 중요한 행동"(위험 시 "오늘 기준으로 재조정")이 눈에 들어옵니다.

### 배지
- 홈의 지연 배지("+2일", "5일 지남", "여유 없음")를 공통 배지 규격(높이 20, 좌우 6, 12px/500)에 맞췄습니다. 변경 전에는 좌우 7px에 굵기 600이어서 파급 예측 화면의 같은 배지와 달랐습니다.

### 포커스 표시 — 2가지 규칙
- **상자형 컨트롤**(버튼·입력창·카드): 1px 선 + 3px 연한 테두리(`--focus-ring`)
- **그 외**(목록 행·내비게이션·링크): 2px 윤곽선. 잘리는 컨테이너 안에서는 안쪽(−2px), 그 외에는 바깥쪽(2px)
- 변경 전에는 연한 테두리만 있어 잘 안 보이는 곳이 8군데, 윤곽선 간격이 1/2/3px로 섞여 있었습니다. **근거:** 키보드 사용자는 포커스 위치를 놓치면 길을 잃습니다. 어디서든 같은 모양이어야 찾기 쉽습니다(WCAG 2.4.7).

### 용어
- "2번 미룸"(홈) / "2회 미룸"(목록·파급 예측·상세) → **"N회 미룸"** 으로 통일. 같은 사실을 다른 말로 쓰면 다른 지표로 오해할 수 있습니다.

## 4. 개별 결함 수정

- **요약 타일 줄바꿈:** 화면 폭 1280px 부근에서 "전체 완료 예상"의 `11/26 (목)`이 두 줄로 꺾여 그 타일만 높이가 달라졌습니다. 다섯 타일의 숫자가 페이지 폭에 맞춰 함께 줄어들도록 바꿔(20~30px) 항상 한 줄, 같은 크기를 유지합니다.
- **설명 문장의 대비:** 페이지 부제와 섹션 설명을 `--text-3`에서 `--text-2`로. **근거:** `--text-3`(#8a8a8a)은 흰 바탕에서 대비 약 3.5:1로 본문 기준(WCAG AA 4.5:1)에 못 미칩니다. `--text-2`(#525252)는 약 7.8:1입니다. 색 토큰 자체는 그대로이고, 문장에는 읽을 수 있는 쪽을 쓰도록 배정만 바꿨습니다. `--text-3`은 날짜·개수 같은 짧은 메타 정보에만 남겼습니다.

## 5. 의도적으로 바꾸지 않은 것

- **색상 전체.** 요청대로 유지했습니다.
- **레이아웃과 정보 구조.** 사이드바, 페이지 폭, 홈 블록 순서, 상세 패널 구성은 그대로입니다.
- **사이드바의 30px 행 높이.** 공통 컨트롤 단계(28/32)와 다르지만 사이드바 안에서는 일관되고, 내비게이션 밀도에 맞춘 값이라 유지했습니다.
- **모든 여백의 토큰화.** 패널 안쪽 여백만 토큰(`--inset-*`)으로 만들고, 나머지 여백은 격자 규칙만 맞췄습니다. 여백은 조합(`12px 8px 12px 12px` 등)이 많아 전부 토큰으로 바꾸면 오히려 읽기 어려워집니다.
- **모바일 터치 영역 확대.** 현재 28~32px로 WCAG AA 최소(24px)는 충족합니다. 44px까지 키우는 것은 밀도에 영향이 커서 별도 판단이 필요합니다.

## 6. 확인한 것

- 타입 검사 통과, 개발 서버에서 14개 경로 모두 정상 응답, 콘솔·서버 오류 없음.
- 브라우저(1280px, 라이트)에서 홈·오늘·작업 상세 패널·새 작업 다이얼로그·명령 팔레트를, 다크 모드로 파급 예측을, 375px 폭으로 홈·설정을 직접 확인했습니다.
- 확인하지 못한 것: 예정·전체 작업·완료 기록·프로젝트·AI/Jev/조직 설정·로그인·초대·OAuth 동의 화면은 변경 후 눈으로 다시 보지 않았습니다(같은 토큰 변환만 적용됨). 다크 모드와 모바일 폭도 위에 적은 화면만 봤고, 실제 iOS 기기 확인은 하지 않았습니다.

## 7. 앞으로 지킬 규칙

새 스타일을 쓸 때 원시 값 대신 토큰을 고릅니다. 요약은 `globals.css` 맨 위 주석에 있습니다.

- 글자 크기는 `var(--fs-*)`, 반경은 `var(--radius-*)`, 시간은 `var(--dur-*)`만 사용
- 테두리 있는 패널의 안쪽 여백은 `var(--inset-sm|--inset|--inset-lg)`, 그 밖의 여백은 16px 미만 2px·이상 4px 단위
- 버튼처럼 생긴 것은 `ui.btn` + 변형(`primary`/`outline`/`ghost`) + 크기(`xs`/`sm`/`lg`)로
- 한 화면에 `primary`는 하나
- 문장은 `--text-2`, 짧은 메타 정보만 `--text-3`
