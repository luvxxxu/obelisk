# Obelisk

단순하지만 핵심에 강한 할 일·일정 관리 앱. **미루기 전에, 무엇이 함께 밀리는지 먼저 보여줍니다.**

- **단순한 모델** — 작업, 프로젝트, 날짜(시작·마감, 필요하면 몇 시 몇 분까지), 선행 작업, 고정 일정. 그게 전부입니다.
- **지연 파급 예측** — 작업을 미루면 뒤따르는 작업이 며칠씩 밀리는지, 어떤 고정 일정(회의·출시일)과 충돌하는지, 프로젝트 완료일이 어떻게 바뀌는지 즉시 계산합니다. 미루기 메뉴, 상세 패널, 타임라인 드래그 어디에서든 적용 전에 미리 보여줍니다.
- **파급 예측 대시보드** — 기한이 지난 작업은 빨라도 오늘 끝난다는 현실을 일정 전체에 반영해서 "지금 이미 밀리고 있는 일정", 하루만 늦어도 전체가 흔들리는 **핵심 작업**, **자꾸 미뤄지는 작업**을 보여줍니다.
- **Jev 판단 보조** — TypeSafe의 판단 모델 Jev(또는 같은 System One API를 쓰는 OpenRouter·Cloudflare Clef 등)를 내 API 키로 연결하면 **우선순위를 자동으로 정하고**, 일이 몰리면 **무엇을 미룰지** 골라 줍니다. 새 작업의 프로젝트·우선순위·고정 여부와 선후 관계도 추천합니다. Jev는 의미만 판단하고 날짜·파급 계산은 지연 예측 엔진이 그대로 맡습니다.
- **약속하기 전에 보여주기** — 작업마다 예상 시간(`~1h30m`)을 적고, 실제 걸린 시간은 ‘진행 중’인 동안 저절로 기록되거나 타이머·직접 입력으로 남깁니다. 이 기록으로 **내 예상이 실제로 몇 배 걸리는지, 첫 마감을 얼마나 지키는지, 하루에 몇 시간을 작업에 쓰는지** 배워서, 일정 전체를 수백 번 돌려 작업마다 **제때 끝낼 확률**과 프로젝트의 **50%·85% 완료일**을 계산합니다. 누가 “언제까지 돼요?”라고 물으면 **다른 일을 하나도 밀지 않고 약속할 수 있는 날**과 **가장 빠른 날(그리고 그때 밀리는 일)**을 바로 보여줍니다.
- **오늘 시간표** — 그날 할 일을 회의와 쉬는 시간 사이 빈 시간에 블록으로 자동 배치합니다(마감 지난 일과 오늘 마감부터, 선행 작업이 먼저, 긴 일은 나눠서, 여러 날짜리 일은 하루 몫만). 블록은 끌어서 옮기고 늘리며, 직접 놓은 블록은 다시 짜도 그대로 둡니다. 모든 공간의 내 일과 회의를 한 하루로 봅니다.
- **자연어 빠른 입력** — `기획서 초안 다음 주 수요일까지 #업무 !높음 ~2h`, `워크숍 11/20~11/22 @고정`. 마감일을 적으면 그 날짜를 지킬 확률이 바로 뜹니다.
- **조직** — 개인 공간은 그대로 두고 여러 조직에 참여합니다. 프로젝트마다 멤버·팀별로 **보기 · 쓰기 · 관리** 권한을 나누고, 담당자와 활동 기록, 초대 링크를 지원합니다. 연결한 AI(MCP)도 계정 권한을 그대로 따릅니다.
- **웹훅** — 작업 생성·완료·미룸 같은 변경과 오늘·내일 마감, 기한 지남, 고정 일정 충돌, 시작·마감 N분 전 알림을 Slack·Discord(한국어 메시지)나 서명된 JSON으로 보냅니다. 반대로 비밀 URL 하나로 GitHub Actions·단축어·Zapier·Slack 슬래시 명령에서 작업을 만들거나 완료할 수 있습니다.
- **AI 완전 지원** — 모든 기능을 MCP 도구 31개 + 프롬프트 3개로 제공하고(OAuth 2.1 내장), 언제 어떻게 쓸지 알려주는 Agent Skill을 함께 배포합니다. Claude, ChatGPT, Claude Code, Codex에서 바로 연결할 수 있습니다.
- **서버 관리** — 직접 띄워 쓰는 서버를 위한 운영자 화면(`/admin`). 가입 방식(열림 · 승인제 · 초대만 · 닫힘)과 메일 주소 확인·도메인 제한을 재배포 없이 바꾸고, 계정 승인·정지·삭제, 설정 점검, 백업 상태, 업데이트 확인, 공지까지. 운영자도 다른 사람의 작업 내용은 볼 수 없습니다.
- **Dokploy 한 번에 배포** — `docker-compose.yml` 하나로 web + backend + Postgres + 매일 백업. 도메인은 web 하나만 연결하면 됩니다.

## 구조

```
obelisk/
├─ packages/core   공용 TypeScript: 타입, zod 스키마, 지연 예측 엔진, 자연어 파서, 뷰 필터
├─ backend         NestJS 12 on Bun — REST API, MCP 서버(/mcp), OAuth 2.1 인가 서버, Jev 연동, Postgres(Drizzle)
├─ web             Next.js 16 on Bun — CSS Modules만 사용 (외부 CSS 라이브러리 없음)
├─ skills/obelisk  Agent Skill (SKILL.md + references + REST 헬퍼 스크립트)
└─ docker-compose.yml
```

지연 예측 엔진(`packages/core/src/impact.ts`)은 순수 함수라서 **브라우저에서는 드래그하는 순간 실시간으로**, 서버에서는 REST·MCP 응답용으로 똑같이 실행됩니다. 백엔드로 Bun + NestJS를 고른 가장 큰 이유입니다.

```
브라우저 ──► web:3000 ──┬─ /            Next.js UI
                        ├─ /api/*       ┐
                        ├─ /mcp         ├─► backend:4000 ──► db:5432
                        └─ /.well-known ┘
Claude / ChatGPT ──► https://도메인/mcp  (OAuth: /.well-known → /oauth/authorize → /api/oauth/token)
```

## Jev 판단 보조

[Jev](https://docs.typesafe.ai/introduction)는 TypeSafe의 판단 모델입니다. 글을 생성하지 않고, 상태(작업 설명)와 타입이 정해진 질문을 받아 **확률과 신뢰도가 붙은 답**을 0.2~0.5초 안에 돌려줍니다. Obelisk는 Jev에게 작업마다 작은 질문 세 개만 묻고, 날짜·파급·충돌 계산은 기존 지연 예측 엔진이 그대로 합니다. 둘을 합치는 가중치는 `packages/core/src/jev.ts`에 있고 테스트로 고정돼 있습니다.

| Jev에게 묻는 것 | 형식 |
|---|---|
| 놓치면 무엇을 잃나 (언젠가 · 가벼운 일 · 꼭 해야 하는 일 · 손해가 큰 일) | Score 0–3 |
| 며칠 미뤄도 괜찮은가 | Noul (예/아니오 확률) |
| 다른 사람이 기다리는가 (내 후속 작업은 제외) | Noul |
| 새 작업: 어느 프로젝트인가 · 고정 일정인가 | Choice + Noul |
| 두 작업의 순서: 먼저 · 나중 · 무관 | Choice |

### 기능

| 기능 | 어디서 | 어떻게 정하나 |
|---|---|---|
| **우선순위 자동 판단** | 홈 Jev 추천 → 우선순위 정리, ⌘K | 중요도가 상한을 정하고, 마감 임박도가 그중 얼마를 지금 적용할지 정합니다. 하루 늦으면 다른 작업이 밀리거나 고정 일정과 부딪히는 작업은 가산점. 세 단계로 나눈 뒤 이유와 확신도를 함께 보여줍니다. |
| **지금 할 일 하나** | 홈 Jev 추천 | 오늘 할 일 중 선행 작업이 다 끝나 바로 시작할 수 있는 것 가운데 점수가 가장 높은 작업. 진행 중인 일을 조금 더 우선합니다. |
| **미룰 작업 고르기** | 홈, 오늘 화면, ⌘K | 하루 처리량(최근 14일 완료 페이스, 직접 조정 가능)을 넘는 날에서 ‘미뤄도 괜찮음 × 덜 중요함’ 순으로 고르고, 이미 여러 번 미룬 일·진행 중인 일·남이 기다리는 일은 뒤로 뺍니다. 옮길 날은 엔진으로 시뮬레이션해서 **고정 일정과 충돌하지 않고** 여유가 남는 가장 가까운 날을 고릅니다. 고정 일정과 다른 사람의 작업은 옮기지 않습니다. 적용은 연쇄 미루기로 하고 한 번에 되돌릴 수 있습니다. |
| **새 작업 자동 분류** | 빠른 입력 | 적은 내용에서 빠진 프로젝트·우선순위·고정 여부를 칩으로 추천. `Tab`으로 모두 적용. |
| **선후 관계 찾기** | 작업 상세 → Jev 연결 제안 | 같은 프로젝트에서 ‘먼저 끝나야 할 일’과 ‘이 작업을 기다릴 일’을 찾습니다. 이미 직·간접으로 이어진 작업은 빼고, 다른 프로젝트 작업은 확신 80% 이상일 때만 제안합니다. |
| **MCP 도구** | Claude · ChatGPT · Claude Code | `suggest_priorities`, `suggest_postpone`, `suggest_dependencies` (읽기 전용, 적용은 기존 도구로) |

### 연결과 자동 적용

- **설정 → Jev**에서 각자 서비스와 키를 넣습니다. TypeSafe·OpenRouter·Cloudflare(Workers AI의 Clef, 하루 10,000 뉴런 무료)는 프리셋으로 고르고, 그 밖의 System One 호환 서버는 **Base URL과 모델**을 직접 적습니다(Base URL 끝에 `/systemone`이 없으면 붙입니다). 사용자가 정한 주소는 매 요청마다 https·공개 주소인지 확인하고, 저장된 키는 다른 호스트로 옮겨 가지 않습니다(호스트를 바꾸면 키를 다시 입력). 한 요청의 질문은 Clef 제한에 맞춰 64개 이하로 나눕니다. 저장 전에 키가 동작하는지 한 번 확인하고, 키는 AES-256-GCM으로 봉인해 DB에 둡니다. 봉인 키는 `SECRET_KEY`이고(없으면 DB 비밀번호에서 파생), 값마다 어느 키로 봉인했는지와 주인(사용자)이 함께 묶여 있어서 다른 계정 행에 복사해도 열리지 않습니다. **운영에서는 `SECRET_KEY`를 꼭 설정하세요** — 그래야 DB 덤프와 DB 비밀번호가 함께 새도 키는 안전합니다. 키 설정은 웹 세션에서만 바꿀 수 있습니다.
- **키 교체**: `SECRET_KEY`를 새 값으로 바꾸고 예전 값을 `SECRET_KEY_PREVIOUS`에 넣은 채 재시작하면, 시작할 때 저장된 키를 모두 새 키로 다시 봉인합니다(로그 `[jev] re-sealed …`). 그 뒤에는 `SECRET_KEY_PREVIOUS`를 지워도 됩니다. `SECRET_KEY`를 처음 설정할 때는 예전 값이 필요 없습니다(DB 비밀번호 키에서 자동으로 옮깁니다). 어떤 키로도 열 수 없는 키는 앱에 **다시 입력 필요**로 표시됩니다.
- 기본은 **제안 후 확인**입니다. **확신이 높으면 바로 적용**을 켜면 확신도 80% 이상인 판단만 반영합니다: 새 작업의 프로젝트·우선순위·고정 여부, 그리고 우선순위가 **비어 있는** 작업. 직접 정한 우선순위는 덮어쓰지 않고, 실행 취소한 작업은 다시 건드리지 않습니다. 미루기와 선후 관계 연결은 언제나 확인을 받습니다.
- 전송되는 것: 작업 제목, 메모 앞부분(360자), 날짜, 프로젝트 이름, 연결된 작업 제목. 이메일·멤버 이름은 보내지 않고, 조직에서는 그 사람이 볼 수 있는 작업만 보냅니다.
- 비용: Jev는 입력 토큰만 과금합니다($0.042 / 100만 토큰). 작업 80개를 한 번 판단하는 데 약 2만 토큰(약 $0.001). 같은 날 내용이 바뀌지 않은 작업은 서버에 6시간 캐시해서 다시 묻지 않습니다.

실제 Jev로 판단 품질 테스트(준비한 한국어 예문만 전송):

```bash
TYPESAFE_API_KEY=… OBELISK_LIVE_JEV=1 bun test backend/test/jev.test.ts
```

## 시간 계획과 완료 확률

지연 예측 엔진이 “이게 밀리면 무엇이 밀리나”에 답한다면, 이 기능은 “이 날짜가 얼마나 확실한가”에 답합니다. 계산은 모두 `packages/core/src/timeplan.ts`(하루 시간표, 시간 기록)와 `odds.ts`(확률, 약속 날짜)의 순수 함수이고 테스트로 고정돼 있습니다.

**예상 시간과 실제 시간**
- 작업마다 예상 시간(분)을 둡니다. 빠른 입력에서는 `~30분`, `~1h30m`, `~2시간`.
- 실제 시간은 세 가지로 쌓입니다: ‘진행 중’으로 바꾸면 자동 기록(완료·되돌리면 멈춤), 타이머(시작/정지), 직접 입력. 한 사람에게 시계는 하나라 다른 작업을 시작하면 앞의 것이 멈춥니다. 자동 기록이 3시간을 넘기면 근무 시간만 셉니다(밤새 진행 중으로 둔 작업이 밤 시간을 차지하지 않게). 완료하면 “실제 1시간 12분 (예상 1시간)”을 보여주고 바로 고칠 수 있습니다.
- 계정을 지운 멤버의 기록은 이름 없이 작업에 남아 합계가 유지됩니다.

**오늘 시간표** (오늘 → 시간표, 설정 → 일정 계획에서 근무 요일·시간·쉬는 시간)
- 계획은 사람마다 따로이고 다른 사람은 볼 수 없습니다. 모든 공간의 내 일(개인 공간 전부, 조직은 내게 배정됐거나 내가 만든 미배정 작업)과 시각이 있는 작업(회의·약속)을 한 하루로 계산합니다.
- 시각이 있는 작업은 그 시간을 차지할 뿐 일로 다시 배치하지 않습니다. 지나간 회의가 열려 있어도 마찬가지입니다.
- “자동으로 채우기”는 미리보기를 먼저 보여주고 저장합니다. 직접 놓거나 옮긴 블록(📌)과 지나간 블록은 다시 짜도 남습니다. 넘치는 시간과 마감 시각을 넘기는 블록을 알려줍니다.

**완료 확률** (파급 예측 → 완료 확률, 홈 위젯, 작업 상세의 마감일 옆)
- 사람마다 작업 큐를 두고 하루씩 진행합니다. 각 날의 용량은 근무 시간 × 집중 비율 − 회의이고, 날마다 조금씩 흔들립니다. 작업은 급한 순(뒤에 기다리는 작업의 마감까지 물려받음)으로, 선행 작업이 끝나야 시작합니다.
- 예상 시간이 있는 작업은 지난 기록의 ‘실제 ÷ 예상’ 비율을 뽑아 길이를 정하고(기록이 적으면 1.25배 쪽으로 기울임), 예상이 없는 작업은 평소 길이로 보되 **첫 마감 대비 실제 완료일 기록**을 함께 따릅니다. 미뤄도 처음 마감일(`tasks.first_due_date`)로 따지고, 기존 작업은 활동 기록에서 처음 마감일을 되찾아 채웠습니다.
- 내 다른 공간의 일도 같은 시간을 쓰므로 부하로 넣고(결과에는 나오지 않음), 동료의 이력은 내가 볼 수 있는 작업에서만 읽습니다. 같은 날에는 같은 답이 나오도록 시드를 고정했고, 작업마다 자기 난수 흐름을 써서 작업 하나를 더하거나 빼도 다른 작업의 운은 그대로입니다(차이가 진짜 차이).

**약속하기 전에** (빠른 입력의 확률 칩, 작업 상세 → 가능한 날짜, ⌘K, MCP `check_commitment`)
- 새 일(또는 기존 작업)을 날짜 d에 끝내기로 하고 일정을 다시 돌려 봅니다. **안전한 날**은 85%에 닿으면서 다른 작업의 확률을 5%p 넘게 깎지 않는 첫날, **가장 빠른 날**은 85%에 닿는 첫날(그리고 그때 위험해지는 작업과 확률 변화), **순서대로 하면**은 끼워 넣지 않았을 때의 50%/85% 완료일입니다.
- 마감을 앞당기면 다른 일보다 먼저 처리되어 오히려 확률이 오르는 구간이 있어서, 가까운 45일은 하루씩 계산하고 그 뒤만 이분 탐색합니다.

## 조직과 권한

계정마다 **개인 공간**이 하나 있고(가입 전 데이터도 모두 여기에 있습니다), 원하는 만큼 **조직**을 만들거나 초대받아 참여할 수 있습니다. 사이드바 왼쪽 위에서 공간을 바꿉니다. 작업 번호(`#12`)는 공간마다 따로 매깁니다.

| 역할 | 할 수 있는 일 |
|---|---|
| 소유자 | 관리자 권한 전부 + 소유자 지정·해제, 조직 삭제 (소유자는 최소 한 명) |
| 관리자 | 모든 프로젝트 관리, 멤버 역할·내보내기, 초대 링크, 팀, 전체 활동 기록 |
| 멤버 | 공유받은 프로젝트만. 설정에 따라 새 프로젝트 만들기 |

프로젝트 권한은 **보기 < 쓰기 < 관리** 세 단계입니다. 쓰기는 작업 추가·수정·삭제·연결, 관리는 이름·보관·삭제·공유·다른 공간으로 옮기기까지입니다. 멤버 한 사람의 권한은 `조직 전체 기본값`, `개인에게 준 권한`, `속한 팀에 준 권한` 중 가장 높은 것입니다.

- **새 프로젝트는 비공개**로 시작합니다. 만든 사람이 관리 권한을 갖고 프로젝트 → 공유에서 사람·팀·조직 전체에 권한을 줍니다.
- 조직에서 **프로젝트 없는 작업**은 만든 사람과 담당자들만 봅니다(관리자도 못 봅니다).
- **담당자**는 작업마다 여러 명(최대 20명)을 지정할 수 있고, 모두 같은 담당자입니다. 그 프로젝트를 볼 수 있는 멤버만 지정할 수 있습니다. 조직에서는 사이드바에 **내 작업**이 생기고, 내가 담당자 중 한 명인 작업이 모입니다. 시간 계획·완료 확률은 담당자마다 자기 몫을 하는 것으로 계산해, 가장 바쁜 담당자의 일정이 끝나는 날을 따릅니다.
- API·웹훅에서 담당자는 배열입니다: 작업의 `assigneeIds`(PATCH 하면 목록 전체가 바뀜), 웹훅 페이로드의 `assignees: [{id, name}]`, 받는 웹훅의 `assignees`. 데이터 이전 파일은 형식 버전 2이며, 버전 1 파일도 그대로 가져올 수 있습니다.
- 공간이 둘 이상이면 **모아보기**(`G` `O`)가 생깁니다. 개인 공간 작업 전부와 각 조직에서 나에게 배정된 작업을 한 화면에 모아 기한 지남 · 오늘 · 앞으로 7일 · 30일 안의 고정 일정으로 보여주고, 날짜별로 어느 공간의 일이 몰리는지도 보여줍니다. 공간마다 그 공간의 권한 그대로 읽으며, 의존 관계는 공간을 넘지 않으므로 지연 예측은 공간별로 따로 합니다. 홈의 **다른 공간** 위젯은 지금 열지 않은 공간의 요약입니다.
- **볼 수 없는 작업은 존재 자체가 드러나지 않습니다**: 목록·의존 관계·지연 예측·활동 기록에서 빠지고, 직접 요청하면 404입니다. 연쇄 미루기가 보기 전용 작업까지 옮겨야 하면 통째로 거절됩니다(이 작업만 미루기는 가능).
- **초대 링크**는 역할·만료·사용 횟수를 정해 만들고, 링크 자체는 해시로만 저장합니다. 가입 방식이 ‘초대만’이어도 초대 링크로는 가입할 수 있고(‘닫힘’이면 이미 있는 계정만 수락), 승인제와 도메인 제한도 건너뜁니다.
- **활동 기록**은 누가 무엇을 언제 바꿨는지와, AI 앱·API 토큰을 거쳤는지를 남깁니다. 작업 상세에는 그 작업의 기록이, 조직 설정 → 활동에는 볼 수 있는 범위의 전체 기록이 나옵니다.
- 개인 공간 프로젝트를 조직으로(또는 조직 사이로) **옮길 수 있습니다**. 작업 번호는 새로 매겨지고, 남는 작업과의 의존 관계는 끊기며, 공유 설정은 초기화됩니다.
- 조직 전체를 **다른 Obelisk 서버로 옮길 수 있습니다**(소유자만, 설정 → 데이터 이전). 가져온 사람을 뺀 멤버는 모두 **가입 대기**에 자리가 남고, 관리자가 건넨 합류 링크로만 들어옵니다. 자세한 내용은 아래 ‘다른 서버로 옮기기’를 보세요.

**API·MCP**: 토큰과 OAuth 연결은 계정 권한을 그대로 씁니다. 공간은 `X-Obelisk-Workspace` 헤더(id)나 `?workspace=`로 고르고, 없으면 계정의 기본 공간(설정 → AI 연결 → AI 기본 공간)을 씁니다. 공유 설정, 멤버, 초대, 팀 관리는 웹 로그인 세션에서만 할 수 있어서 AI가 접근 범위를 넓힐 수 없습니다.

## 웹훅

**설정 → 웹훅**에서 지금 열린 공간의 웹훅을 관리합니다. 개인 공간은 본인이, 조직은 소유자·관리자만 다룰 수 있고, 웹 로그인 세션에서만 바꿀 수 있어서 API 토큰이나 AI 앱이 공간의 변경 내용을 다른 주소로 빼돌릴 수 없습니다.

**보내는 웹훅**
- 이벤트를 골라 받습니다: 새 작업 · 완료 · 수정 · 미룸 · 삭제 · 선행 작업, 프로젝트 변경, 멤버·팀·초대(조직), 그리고 일정 알림(오늘 마감 · 내일 마감 · 기한 지남 · 고정 일정 충돌 · 시작 시각 알림 · 마감 시각 알림). 프로젝트 범위를 좁힐 수 있습니다.
- 삭제(`task.deleted`)는 작업을 휴지통으로 옮길 때 가고, 작업이 목록에서 빠졌으니 `task`는 `null`입니다. 휴지통에서 되살린 작업은 새 작업을 받는 웹훅에 `task.restored` 이벤트로 갑니다(따로 고를 항목은 없음). 프로젝트를 작업과 함께 지우면 작업마다가 아니라 프로젝트 이벤트 하나만 갑니다.
- 변경 이벤트는 그 변경과 **같은 트랜잭션**에서 대기열에 들어가므로 취소된 변경은 보내지 않고, 웹훅 쪽 문제로 변경이 실패하지도 않습니다. 일정 알림은 5분마다 확인해서 정한 시각(기본 오전 9시, 만든 사람의 시간대) 이후에 작업마다 하루 한 번 보냅니다. 고정 일정 충돌에는 시작점이 된 늦은 작업이 함께 담깁니다. 마감 시각이 있는 작업은 그 시각이 지나면 당일에도 ‘기한 지남’으로 잡힙니다.
- 시각 알림은 시작·마감 시각이 정해진 작업에만, 정한 시간(정각 · 5분 · 10분 · 15분 · 30분 · 1시간 · 2시간 · 하루 전, 기본 30분) 전에 1분 단위로 확인해서 보냅니다. 페이로드의 `alert.at`(`YYYY-MM-DDTHH:MM`)과 `alert.minutesLeft`로 남은 시간을 알 수 있고, 시각을 바꾸면 새 시각 기준으로 다시 한 번 보냅니다.
- URL이 Slack·Discord면 한국어 메시지로(멘션은 울리지 않음), 그 밖에는 JSON으로 보냅니다. 모든 요청에 `X-Obelisk-Event`, `X-Obelisk-Delivery`, `X-Obelisk-Timestamp`, `X-Obelisk-Signature: sha256=HMAC(서명 키, "<timestamp>.<본문>")`가 붙습니다. 서명 키는 `SECRET_KEY`로 봉인해 저장하고 만들 때 한 번만 보여 줍니다.
- 실패하면 1분 · 5분 · 30분 · 2시간 · 6시간 뒤에 다시 보냅니다(5xx, 408, 429, 연결 오류). 4xx는 바로 실패로 처리하고, 연속 10번 실패하면 웹훅을 자동으로 끕니다. 전달 기록(보낸 본문 · 응답)은 30일 동안 남고 다시 보내기·테스트 보내기를 할 수 있습니다.
- 조직의 인박스(프로젝트 없는) 작업은 비공개라 보내지 않습니다. 운영에서는 내부망·루프백 주소로 보낼 수 없고(SSRF 방지), 리디렉션도 따라가지 않습니다. 사내망 수신기가 필요하면 `WEBHOOK_ALLOW_PRIVATE=true`를 설정하세요.

**받는 웹훅**
- 비밀 URL(`/api/hooks/obh_…`, 해시로만 저장)로 POST하면 **만든 사람의 권한**으로 실행되고 활동 기록에 “웹훅 ‘이름’ 통해”로 남습니다.
- 텍스트: `보고서 초안 내일 오후 3시 !높음 #런칭`(빠른 추가 문법, 둘째 줄부터 메모), `#12 완료`, `#12 시작`, `#12 금요일까지`, `#12 내일 15:30까지`
- JSON: `{"title":"배포 확인","dueDate":"2026-11-20","dueTime":"15:30","priority":"high","project":"런칭","assignees":["me","민겸"]}` 또는 `{"action":"complete","task":"#12"}`(complete · start · cancel · reopen · update). `dueDate`에 `2026-11-20T15:30`이나 `내일 오후 3시`처럼 시각을 함께 써도 되고, 오프셋이 붙은 시각(`…T06:30:00Z`)은 만든 사람의 시간대로 바꿔 읽습니다. 자정(`T00:00:00`)은 날짜만 있는 것으로 봅니다.
- 새 작업이 들어갈 프로젝트를 정할 수 있고, 그렇게 하면 기존 작업 수정도 그 프로젝트 안으로 제한됩니다. 기존 작업 수정은 웹훅마다 끌 수 있습니다. Obelisk가 보낸 요청은 받지 않아 웹훅끼리 무한히 돌지 않습니다.

## 다른 서버로 옮기기

**설정 → 데이터 이전**에서 개인 공간이나 조직을 다른 Obelisk 서버로 옮깁니다. 방법은 두 가지이고, 받는 쪽은 둘 다 미리보기를 보여 준 뒤 **가져오기**를 누르면 한 트랜잭션으로 들어갑니다.

1. **파일로**: 원래 서버(A)에서 **파일로 내려받기** → 새 서버(B)의 **가져오기**에 파일을 올립니다(JSON, `.gz`도 됨, 최대 64MB. 브라우저가 gzip으로 압축해 올립니다). 암호(8자 이상)를 정하면 Jev 키와 웹훅 서명 키를 그 암호로 잠가(scrypt + AES-256-GCM) 함께 담고, 정하지 않으면 비밀값 없이 담깁니다. 이때 Jev 키는 B에서 다시 입력하고 웹훅 서명 키는 B가 새로 만듭니다.
2. **바로 보내기**: A에서 **이전 링크 만들기** → `https://A/settings/migrate#omg_…` 링크를 B의 가져오기 칸에 붙여 넣으면 B 서버가 A에서 직접 받아 옵니다. 링크는 30분 동안 한 번만 쓸 수 있고(해시로만 저장), 새 링크를 만들면 쓰지 않은 이전 링크는 바로 막힙니다. 비밀값도 함께 옵니다. B는 링크의 서버 주소만 따라가고, 운영에서는 https 공인 주소만 허용하며(내부망·루프백 거절, 리디렉션 안 따름) 같은 서버 주소는 거절합니다.

**누가**: 개인 공간은 본인, 조직은 **소유자만** 내보낼 수 있습니다(모든 멤버의 비공개 작업과 웹훅 비밀값이 들어 있기 때문). 모두 웹·iOS 로그인 세션에서만 가능하고 API 토큰·AI 앱으로는 할 수 없습니다. 받는 쪽은 로그인한 누구나 가져올 수 있습니다.

**어디로**: 개인 공간은 **내 개인 공간에 합쳐집니다**. 비어 있으면 `#번호`를 그대로 두고, 작업이 있으면 원래 번호 순서대로 기존 작업 뒤에 새 번호를 매깁니다. 조직은 **새 조직**으로 만들어지고 가져온 사람이 소유자가 됩니다.

**옮겨지는 것**: 프로젝트(색·순서·보관·공유 설정), 작업(번호·순서·미룬 횟수·완료 시각·만든 시각 그대로), 의존 관계, 팀과 팀원, 사람·팀·조직 전체 권한, 활동 기록 전체(원래 시각, 새 id로 바꿔 연결), 조직 사진, 보내는 웹훅, 받는 웹훅(새 주소로). 개인 공간이면 **내 설정도 가져오기**로 시간대, 홈 배치, 프로필 사진, Jev 설정과 키를 옮깁니다(기본 공간은 바꾸지 않음). 미리보기에는 Jev 주소가 TypeSafe 기본이 아니면 그 호스트도 표시됩니다.
- 보내는 웹훅은 **꺼진 채로** 들어옵니다(이미 보낸 일정 알림을 다시 보내지 않도록). 확인한 뒤 켜세요. 비밀값이 함께 왔으면 서명 키가 그대로라 받는 쪽을 고칠 필요가 없습니다.
- 받는 웹훅은 B에서 **새 비밀 주소**로 만들어집니다. 가져온 직후 결과 화면에 한 번만 보여 주니, 요청을 보내는 곳의 주소를 바꾸세요(화면을 닫으면 다시 볼 수 없고, 웹훅 설정에서 주소를 새로 만들 수는 있습니다). A의 옛 주소는 B에서 작동하지 않습니다.
- **API 토큰은 옮기지 않습니다.** 결과 화면에 원래 토큰 이름을 보여 주니 B의 설정 → AI 연결에서 새로 만드세요.
- 옮겨지지 않는 것: 로그인 세션, API 토큰, AI 앱 연결(OAuth, 새 서버에서 다시 연결), 웹훅 전송 기록, 초대 링크, 비밀번호 재설정 링크.
- 파일에는 토큰이나 웹훅 주소의 해시를 담지 않고, 담긴 파일(예전 형식)을 가져와도 해시는 쓰지 않습니다. 만든 파일 하나로 B에서 남의 토큰처럼 행세할 수 없게 하기 위해서입니다.
- 파일마다 내보내기 id가 있어서 같은 파일을 두 번 가져오려 하면 미리보기에 알려 주고, 확인해야만 한 번 더 가져옵니다. 같은 가져오기가 동시에 두 번 들어와도 한 번만 들어가고, 응답이 중간에 끊겨도 화면이 서버에 결과를 다시 물어 확인합니다.
- 이미 다른 서버에서 가져온 조직을 또 옮기면, 아직 가입 대기인 사람과 떠난 멤버가 남긴 기록(만든 작업·활동)도 그대로 따라갑니다.

**조직 멤버**: 가져올 때 원래 조직의 사람마다 이렇게 됩니다.
- 내보낸 사람은 **가져온 사람**이 됩니다(이메일이 달라도). 새 조직에 처음부터 들어 있는 사람은 이 한 명뿐입니다.
- 나머지는 모두 **가입 대기**(조직 설정 → 멤버)에 자리가 남습니다. B에 같은 이메일의 계정이 있어도 마찬가지이고, 미리보기와 가입 대기 목록에 ‘같은 이메일 계정이 있어요’로만 표시됩니다. 그 사람의 프로젝트·팀 권한, 담당 작업, 만든 작업·프로젝트·웹훅, 활동 기록의 이름은 비워 둔 채 기다리다가 합류하는 순간 한꺼번에 넘어갑니다.
- 들어오는 방법은 두 가지입니다. 하나는 **합류 링크** `https://B/invite/obr_…`입니다. 관리자가 한 사람씩 **링크 만들기**로 복사해 건네거나, 메일 서버(`SMTP_URL`)가 있으면 **메일로 보내기** 또는 가져오기 결과 화면·가입 대기의 **모두에게 메일 보내기**로 예약된 이메일에 보냅니다. 링크로 가입하거나 로그인해 수락하면 이메일과 관계없이 그 자리로 들어옵니다(이미 멤버인 계정은 역할은 그대로 두고 작업과 권한만 이어받습니다). 한 번만 쓸 수 있고, 새로 만들면 전에 만든 링크는 끊깁니다. 가입 방식이 ‘초대만’이어도 가입할 수 있습니다.
- 다른 하나는 **메일 주소 확인**입니다. B에서 그 이메일을 확인한 계정(가입 때 확인 메일, 설정의 ‘확인 메일 보내기’, 이메일 바꾸기)은 링크 없이 바로 그 자리로 들어갑니다. 가져올 때 이미 확인된 계정이 있으면 그 자리에서 들어오고, 결과 화면에 몇 명인지 나옵니다. 메일함을 연 것이 증명이기 때문입니다.
- 확인하지 않은 계정은 같은 이메일로 가입해도 들어오지 않고, 관리자 목록에 표시만 됩니다. 조직 관리자 **승인**은 없습니다. 관리자는 그 계정이 정말 그 사람인지 알 수 없기 때문입니다.
- 원래 조직을 떠났지만 작업이나 기록에 이름이 남은 사람은 **예전 멤버**로 자리만 남아(멤버 역할), 관리자가 링크를 건네면 남긴 기록을 돌려받습니다. 모두에게 메일 보내기에는 들어가지 않습니다.

> **보안 메모**: 가입만으로는 이메일 소유가 확인되지 않습니다(서버 관리에서 메일 확인을 켜기 전까지). 그래서 이메일이 같다는 것만으로는 어떤 권한도 주지 않고, 관리자가 그 사람에게 직접 건넨(또는 그 이메일로 보낸) 합류 링크를 연 사람이나 그 주소로 온 확인 메일을 연 사람만 자리를 채웁니다. 링크를 받았다는 것이 증명입니다. 소유자 자리는 소유자만 링크를 만들 수 있습니다. 파일에는 다른 서버의 토큰·웹훅 주소 해시가 없고 있어도 쓰지 않으므로, 손으로 만든 파일로 B의 누군가로 행세할 수 없습니다. 받는 웹훅은 만든 사람의 권한으로 실행되므로, 만든 사람이 아직 없으면 가져온 사람 이름으로 옮겨집니다. 미리보기·가져오기는 사람마다 한 번에 하나, 서버 전체로 두 개까지만 동시에 처리하고 횟수도 제한합니다.

## 서버 관리

Obelisk는 직접 띄워 쓰는 프로젝트라서 서버마다 **운영자**가 있습니다. 운영자는 사이드바 아래 계정 메뉴 → **서버 관리**(`/admin`)에서 서버 전체를 다룹니다. 조직의 소유자·관리자와는 별개의 역할이고, 둘 다일 수도 있습니다.

**운영자 정하기**
- 새 서버에서는 **처음 가입한 계정**이 운영자가 됩니다(가입 방식과 관계없이 첫 계정은 언제나 가입할 수 있습니다).
- 계정은 있는데 운영자가 없는 서버(서버 관리가 생기기 전부터 쓰던 서버, 운영자가 모두 떠난 서버)는 백엔드가 시작할 때마다 로그에 일회용 링크를 남깁니다.
  ```
  [obelisk] This server has no operator yet: sign in with the account that should run it, then open this one-time link within 24h …
  [obelisk]   https://obelisk.example.com/claim-admin#oac_…
  ```
  운영자가 될 계정으로 로그인한 채 그 링크를 열면 됩니다(Dokploy → 서비스 → Logs의 `backend`). 링크는 24시간 동안 한 번만 쓸 수 있고 다시 시작하면 새로 만들어집니다. 로그는 서버를 띄운 사람만 볼 수 있다는 것이 증명입니다. 운영자가 있는데도 모두 접근할 수 없게 됐다면 `ADMIN_CLAIM=true`로 다시 시작해 같은 링크를 받고, 쓴 뒤에는 끄세요.
- 운영자는 **사용자** 탭에서 다른 계정을 운영자로 지정·해제합니다. 운영자는 최소 한 명 있어야 하고, 정지나 삭제는 운영자에서 해제한 뒤에만 됩니다.

**운영자가 볼 수 있는 것**: 이름, 이메일, 가입일, 마지막 접속, 소속 조직·AI 연결·토큰 **개수**, 조직 이름과 크기(멤버·프로젝트·작업 수), 서버 전체 용량. **작업 제목이나 내용, 프로젝트 이름은 볼 수 없고**, 다른 사람으로 로그인하는 기능도 없습니다. 서버 관리는 웹·iOS 로그인 세션에서만 열리고 API 토큰·AI 앱(MCP)으로는 다룰 수 없습니다. 운영자가 한 일은 **기록** 탭에 남습니다.

| 탭 | 하는 일 |
|---|---|
| 개요 | 확인할 것(승인 대기, 소유자 없는 조직, 새 버전, 설정 경고, 실패 중인 웹훅), 사용량, 버전과 업데이트 확인, 백업, 설정 점검(비밀값은 설정 여부만)과 테스트 메일 |
| 사용자 | 검색·필터(승인 대기 · 메일 확인 전 · 정지됨 · 운영자), 승인·거절, 정지·해제, 비밀번호 재설정 링크, 메일 확인 없이 허용, 운영자 지정·해제, 계정 삭제 |
| 조직 | 조직 목록(이름과 크기만), 소유자가 모두 정지된 조직에 멤버 중 한 명을 소유자로 지정 |
| 가입 | 가입 방식, 메일 주소 확인, 가입할 수 있는 도메인, 조직 만들기(누구나 · 운영자만), 서버 초대 링크 |
| 공지 | 모든 화면 위의 공지 배너, 모든 사용자에게 메일 |
| 기록 | 운영자가 한 일 |

**가입 방식** (바로 적용, `SIGNUP_MODE`는 처음 값으로만 쓰임)

| 방식 | 누가 계정을 만드나 |
|---|---|
| 열림 | 누구나 |
| 승인제 | 누구나 신청하고, 운영자가 승인하면 쓸 수 있음. 신청이 오면 운영자에게 메일(SMTP가 있을 때). 거절하면 그 계정은 삭제 |
| 초대만 | 조직 초대 링크, 합류 링크, 서버 초대 링크가 있는 사람만 |
| 닫힘 | 아무도. 초대 링크로도 새 계정은 만들 수 없음 |

- **서버 초대 링크**(`/signup?invite=osi_…`)는 조직에 넣지 않고 서버 가입만 허용합니다. 쓸 수 있는 횟수(1 · 5 · 25 · 제한 없음)와 만료(1일 · 7일 · 30일 · 없음)를 정하고, 링크는 만들 때 한 번만 보여 줍니다(해시로만 저장).
- 초대 링크로 가입하면 승인과 도메인 제한을 건너뜁니다. 초대한 사람이 보증하는 셈이기 때문입니다.

**메일 주소 확인** (`SMTP_URL` 필요)
- **새 계정은 메일 확인 필수**를 켜면 새로 가입한 계정은 메일로 받은 링크(`/verify-email#oev_…`, 24시간, 한 번)를 열어야 앱을 쓸 수 있습니다. 그 전에는 ‘메일 주소를 확인해 주세요’ 화면에서 메일을 다시 받거나 잘못 적은 주소를 고칠 수 있습니다. **지금 있는 계정은 그대로 쓰고** 설정 → 일반 → 이메일에 ‘확인 전’으로 보이며, 언제든 확인 메일을 받을 수 있습니다.
- **가입할 수 있는 도메인**(예: `company.com`)을 적으면 초대 없이 가입하는 사람은 그 도메인 주소만 쓸 수 있고, 주소 확인도 함께 합니다. 하위 도메인은 따로 적어야 합니다.
- 확인된 주소로 할 수 있는 것: 다른 서버에서 옮겨 온 조직의 가입 대기 자리에 **링크 없이 합류**, 그리고 **이메일 바꾸기**(설정 → 일반 → 이메일 → 바꾸기: 비밀번호를 넣으면 새 주소로 링크를 보내고, 열면 바뀌며 예전 주소로도 알림이 갑니다).
- 메일이 오지 않는 사람은 운영자가 **메일 확인 없이 허용**할 수 있습니다. 이때 그 계정은 ‘확인 전’으로 남아 위의 합류에는 쓰이지 않습니다.

**정지**: 바로 로그아웃되고, API 토큰과 AI 연결이 끊기고(정지를 풀어도 새로 만들어야 함), 그 사람이 만든 받는 웹훅이 멈춥니다. 작업·프로젝트·조직 자리는 그대로입니다. 로그인하면 ‘정지됐어요’라고 나오는데, 비밀번호가 맞을 때만 그렇게 답해서 정지 여부로 계정 존재를 알아낼 수 없습니다.

**삭제**: 본인이 탈퇴할 때와 같은 규칙입니다(다른 멤버가 있는 조직의 마지막 소유자면 거절). 확인을 위해 그 계정의 이메일을 입력해야 합니다. 함께 쓰던 조직의 활동 기록에는 ‘서버 운영자가 계정을 삭제해 조직을 떠났습니다’로 남습니다.

**비밀번호 재설정 링크**: 메일 서버가 없거나 메일이 오지 않는 사람에게 60분짜리 재설정 링크를 만들어 직접 전합니다(메일로 보낼 수도 있음). 운영자가 비밀번호를 정하거나 볼 수는 없습니다.

**업데이트 확인**: 이미지를 빌드할 때 커밋을 `/app/build-info.json`에 새겨 두고(`.git`의 HEAD와 refs만 빌드에 들어감), 몇 시간마다 GitHub의 공개 저장소(`UPDATE_REPO`, 기본 `luvxxxu/obelisk`의 `main`)와 비교해 새 커밋 수와 내용을 보여 줍니다. 서버가 GitHub에 요청하는 것이 싫으면 개요에서 끄면 됩니다. 포크를 운영한다면 `UPDATE_REPO`를 자기 저장소로 바꾸세요. `.git` 없이 빌드하는 환경은 빌드 인자 `OBELISK_COMMIT`으로 커밋을 넘길 수 있습니다.

**백업 상태**: `docker-compose.yml`이 `obelisk-backups` 볼륨을 backend에 **읽기 전용**으로 연결해서 마지막 백업 시각·크기·개수를 보여 주고, 하루가 넘도록 새 백업이 없으면 경고합니다. 백업 파일을 내려받는 기능은 없습니다.

**공지**: 배너는 모든 사용자 화면 맨 위에 한 줄로 보이고(300자), 닫으면 그 브라우저에서는 내용이 바뀔 때까지 다시 보이지 않습니다. 전체 메일은 정지되지 않고 가입이 끝난 계정(또는 메일을 확인한 계정만)에 한 통씩 1.5초 간격으로 보내고, 진행 상황을 보여 주며 멈출 수 있습니다. 메일함 SMTP는 하루 보내기 한도가 있으니(Gmail 약 500통) 사용자가 많으면 나눠 보내세요.

`migration-smoke.ts`는 서로 다른 DB와 `SECRET_KEY`로 띄운 서버 두 개(A → B)를 상대로 조직 파일 내보내기(암호)·가져오기, 번호·권한·기록·사진, 같은 이메일 계정도 가입 대기로만 남는지와 합류 링크로 들어오는지(이미 멤버인 경우 포함), 모두에게 메일 보내기(메일 서버 없으면 400), 승인 경로가 없는지, 꺼진 채 들어온 웹훅의 서명 키, 받는 웹훅이 새 주소로만 작동하는지, API 토큰이 옮겨지지 않는지, 이전 링크로 개인 공간 옮기기(설정·Jev 키·번호 다시 매기기), 링크 일회성과 중복 가져오기를 확인합니다. 두 서버 모두 `SIGNUP_MODE=open`이 필요합니다. A는 개발 모드(메일을 로그로 ‘보냄’), B는 `NODE_ENV=production`에 `SMTP_URL` 없이(메일 불가) `MIGRATION_ALLOW_PRIVATE`·`WEBHOOK_ALLOW_PRIVATE`·`JEV_ALLOW_PRIVATE=true`로 띄웁니다. 127.0.0.1:4297·4298에 가짜 웹훅 수신기와 Jev 서버를 띄웁니다.

```bash
bun backend/scripts/admin-smoke.ts http://localhost:3000
```

`admin-smoke.ts`는 서버 관리 전체(누가 들어올 수 있는지, 가입 방식 네 가지, 승인과 게이트 응답, 서버 초대 링크 일회성, 도메인 제한과 메일 확인, 정지된 계정의 로그인·API 토큰, 마지막 운영자, 소유자 없는 조직 복구, 조직 만들기 제한, 공지, 계정 삭제, 운영 기록)를 확인하고 서버 설정을 원래대로 돌려 놓습니다. 빈 DB면 첫 계정으로 운영자가 되고, 이미 계정이 있으면 `OBELISK_ADMIN_EMAIL`·`OBELISK_ADMIN_PASSWORD`로 운영자 계정을 알려 주세요.

## Dokploy 배포

**준비**: Dokploy 서버의 공인 IP를 가리키는 도메인 A 레코드(예: `obelisk.example.com → 서버 IP`), 그리고 서버의 80·443 포트가 외부에서 열려 있어야 Let's Encrypt 인증서가 발급됩니다. Claude·ChatGPT 커넥터는 https 주소만 받습니다.

1. Dokploy → 프로젝트 → **Create Service → Compose**
2. **General** 탭: Provider는 GitHub, 저장소 `obelisk`, 브랜치 `main`, Compose Path `./docker-compose.yml` → Save
3. **Environment** 탭:
   ```
   PUBLIC_URL=https://obelisk.example.com
   POSTGRES_PASSWORD=영문과숫자로된긴비밀번호
   SIGNUP_MODE=first
   ```
   비밀번호는 `openssl rand -hex 24`로 만들면 됩니다. 한 번 정한 뒤에는 바꾸지 마세요(DB 볼륨이 첫 비밀번호로 초기화됩니다).
4. **Domains** 탭 → Add Domain → Service `web`, Host `obelisk.example.com`, Path `/`, Container Port `3000`, HTTPS 켜기, Certificate `Let's Encrypt`
5. **Deploy**. 끝나면 바로 접속해서 가입하세요. 첫 계정이 **서버 운영자**가 되고, `SIGNUP_MODE=first`이면 그 뒤에는 초대 링크로만 가입할 수 있습니다. 가입 방식은 나중에 서버 관리(`/admin`) → 가입에서 재배포 없이 바꿉니다.
6. (선택) General 탭의 **Autodeploy**를 켜면 `main`에 push할 때마다 다시 배포됩니다.

> `PUBLIC_URL`은 반드시 실제로 접속하는 https 주소와 같아야 합니다. OAuth 메타데이터와 MCP 리소스 주소, 세션 쿠키의 Secure 속성이 이 값으로 정해집니다. 다르면 설정 → AI 연결 화면에 경고가 표시되고, 백엔드 로그에도 `WARNING`이 찍힙니다.

배포 구성:

| 서비스 | 역할 | 외부 노출 |
|---|---|---|
| `web` | Next.js UI + `/api`·`/mcp`·`/.well-known` 프록시 | 도메인(Traefik)만 |
| `backend` | NestJS API, 시작할 때 마이그레이션 자동 적용, `/api/health`가 DB까지 확인 | 없음 |
| `db` | Postgres 17, 데이터는 `obelisk-db` 볼륨 | 없음 |
| `backup` | 매일(그리고 배포할 때마다) `pg_dump`를 `obelisk-backups` 볼륨에 저장, 14일 보관 | 없음 |

모든 컨테이너는 로그를 10MB × 3개까지만 남겨서 디스크가 차지 않습니다.

### 백업과 복구

백업 파일은 `obelisk-backups` 볼륨에 `obelisk-YYYYMMDD-HHMMSS.dump`(pg_dump custom 형식)로 쌓입니다. 서버 밖에도 보관하려면 Dokploy의 **Volume Backups**에서 이 볼륨을 S3 대상으로 예약하세요.

목록 보기와 복구(Dokploy → 서비스 → Logs 옆 터미널, 또는 서버에서 `docker exec -it <backup 컨테이너> sh`):

```bash
ls -lh /backups
```

```bash
pg_restore --clean --if-exists -d obelisk /backups/obelisk-20261115-030000.dump
```

복구 중에는 Dokploy에서 `web`·`backend`를 잠시 멈추는 것이 안전합니다.

### 업데이트

`main`에 push하고 Dokploy에서 **Deploy**(Autodeploy를 켰다면 자동). 새 마이그레이션은 백엔드가 시작할 때 적용되고, 배포 직전 상태는 `backup` 서비스가 다시 시작하면서 자동으로 덤프합니다. 서버 관리 → 개요의 **버전**에서 공개 저장소보다 몇 커밋 뒤처졌는지 볼 수 있습니다.

서버 관리가 생기기 전부터 쓰던 서버는 이 업데이트를 배포한 뒤 `backend` 로그에서 운영자 링크(`/claim-admin#oac_…`)를 찾아 운영자가 될 계정으로 여세요(위 ‘서버 관리’ 참고).

### 환경 변수

| 변수 | 서비스 | 설명 |
|---|---|---|
| `PUBLIC_URL` | backend | 외부에서 접속하는 https 주소 (필수) |
| `POSTGRES_PASSWORD` | db, backend, backup | DB 비밀번호 (필수, URL에 들어가므로 영문·숫자만) |
| `SIGNUP_MODE` | backend | 처음 가입 방식: `first`(기본, 첫 계정 뒤에는 초대만) · `open` · `approval` · `invite` · `closed`(예전처럼 초대 링크는 허용 = `invite`). 운영자가 서버 관리에서 고르면 그 값이 우선 |
| `ADMIN_CLAIM` | backend | (선택) `true`면 운영자가 있어도 시작할 때 운영자 링크를 로그에 남김(모든 운영자가 접근을 잃었을 때). 쓴 뒤 끄세요 |
| `UPDATE_REPO` · `UPDATE_BRANCH` | backend | (선택) 업데이트 확인이 비교할 공개 저장소와 브랜치, 기본 `luvxxxu/obelisk` · `main` |
| `BACKUP_DIR` | backend | compose가 `/backups`로 정함(백업 볼륨을 읽기 전용으로 연결). 서버 관리의 백업 상태가 읽는 곳 |
| `BACKUP_KEEP_DAYS` | backup, backend | 백업 보관 일수, 기본 `14` |
| `BACKEND_URL` | web (빌드 인자) | web이 API를 찾는 내부 주소, 기본 `http://backend:4000` |
| `SECRET_KEY` | backend | (권장) 사용자 Jev 키를 봉인하는 비밀값, `openssl rand -base64 32`. 없으면 DB 비밀번호에서 파생하고 시작할 때 경고합니다 |
| `SECRET_KEY_PREVIOUS` | backend | (선택) `SECRET_KEY`를 바꿀 때 예전 값(쉼표로 여러 개). 한 번 시작해 다시 봉인되면 지워도 됩니다 |
| `JEV_MODEL` | backend | (선택) TypeSafe 기본 모델, 기본 `jev-latest` (사용자가 모델을 정하면 그쪽이 우선) |
| `MIGRATION_ALLOW_PRIVATE` | backend | (선택) `true`면 ‘다른 서버에서 가져오기’가 내부망·http 주소의 서버에서도 받아 옴(같은 LAN의 두 서버, 테스트용). 운영 기본은 꺼짐 |
| `JEV_ALLOW_PRIVATE` | backend | (선택) `true`면 사용자 Jev Base URL로 내부망·http 주소도 허용(자체 서버 테스트용). 운영 기본은 꺼짐 |
| `SMTP_URL` | backend | (선택) 비밀번호 재설정 메일을 보낼 **내 메일함의 SMTP**, 예: `smtps://아이디@gmail.com:앱비밀번호@smtp.gmail.com:465`. 아래 ‘메일 설정’ 참고. 없으면 운영에서는 ‘비밀번호 찾기’가 숨겨지고, 개발에서는 메일 내용을 백엔드 로그에 출력합니다 |
| `MAIL_FROM` | backend | (선택) 보내는 사람. 기본은 `SMTP_URL`의 로그인 주소(예: `Obelisk <아이디@gmail.com>`), 로그인이 주소가 아니면 `Obelisk <no-reply@PUBLIC_URL의 호스트>`. 메일함 SMTP는 그 메일함 주소로만 보낼 수 있으니 비워 두고, Cloudflare처럼 도메인으로 보낼 때는 `Obelisk <no-reply@내도메인>`으로 적습니다 |

## AI 연결

MCP 주소: `https://도메인/mcp` (Streamable HTTP, stateless). 앱의 **설정 → AI 연결**에 클라이언트별 안내, 토큰 발급, 연결된 앱 관리가 모두 있습니다.

| 클라이언트 | 방법 |
|---|---|
| Claude (웹·데스크톱) | Customize → Connectors → Add → Add custom connector → URL 입력, 인증은 Detected 그대로 → Connect → Obelisk 승인 화면에서 허용 (Team·Enterprise는 Owner가 Organization settings → Connectors에서 추가) |
| ChatGPT | Plugins → + → Add custom MCP server → URL, 인증 OAuth → Create as a plugin → 설치 후 **Work** 탭 새 대화에서 `@Obelisk` (Codex에 추가한 MCP는 ChatGPT 대화와 공유되지 않음) |
| Claude Code | `claude mcp add --transport http obelisk https://도메인/mcp` 후 `/mcp`에서 로그인 |
| Codex | `~/.codex/config.toml`에 `url` + `bearer_token_env_var = "OBELISK_TOKEN"` |
| 기타 | OAuth 2.1(DCR+PKCE) 또는 `Authorization: Bearer obk_…` 헤더 |

**Agent Skill**: 앱에서 `obelisk-skill.zip`을 받으면 서버 주소가 미리 채워져 있습니다. Claude는 설정 → 기능 → Skills에 업로드, Claude Code는 `~/.claude/skills/obelisk`, Codex는 `~/.codex/skills/obelisk`에 풉니다.

### 대화 안의 카드 (MCP Apps)

Claude와 ChatGPT에서는 읽기·계획 도구 12개의 결과가 대화 안에 **Linear 스타일 카드**로 표시됩니다. 작업 목록, 작업 상세, 지연 파급 타임라인, 병목, 프로젝트 카드가 있고, 카드에서 바로 완료 체크와 시뮬레이션한 미루기 적용을 할 수 있습니다(모델에게도 알려집니다). 카드는 외부 리소스 없는 단일 HTML(`backend/src/ai/widget/`)이고, URI에 내용 해시가 들어가서 배포하면 클라이언트 캐시가 자동으로 갱신됩니다.

카드를 못 띄우는 클라이언트(Claude Code, Codex)도 같은 스타일의 마크다운(`○ \`#12\` 제목 · 런칭 · 금요일`)을 받습니다. 서버는 `initialize` 때 클라이언트가 MCP Apps를 지원하는지 보고, 카드 내용을 반복하지 말지 또는 마크다운을 그대로 쓸지 모델 지침을 고릅니다.

카드 개발용 로컬 호스트(실제 데이터를 바꾸니 데모 계정에서 쓰세요):

```bash
bun backend/scripts/preview-cards.ts http://localhost:3000
```

### OAuth

- RFC 8414 / 9728 메타데이터: `/.well-known/oauth-authorization-server`, `/.well-known/oauth-protected-resource[/mcp]`
- RFC 7591 동적 클라이언트 등록 + Client ID Metadata Document(https URL client_id)
- Authorization Code + PKCE(S256만), 1시간 access token, 90일 회전식 refresh token
- 토큰·코드는 모두 SHA-256 해시로만 저장

## 지연 예측 모델

- 작업은 `[시작일, 마감일]`을 차지합니다. 마감일만 있으면 하루짜리 작업입니다.
- 선행 작업은 finish-to-start: B는 A의 마감일 당일부터 시작할 수 있습니다.
- A가 늦어지면 B는 **새로 생기는 겹침만큼만** 밀립니다. 사이의 여유는 먼저 흡수되고(흡수됨), 원래 어긋나 있던 일정은 더 나빠지지 않습니다.
- 밀리는 작업은 기간을 유지한 채 이동합니다. 여러 선행 작업이 있으면 가장 늦은 쪽이 기준입니다.
- **고정 일정은 절대 움직이지 않고** 충돌로 보고되며, 파급은 거기서 멈춥니다.
- 완료·취소된 작업은 제약이 되지 않고, 날짜 없는 작업은 지연을 그대로 다음 작업에 전달합니다.

자세한 설명과 예시: [skills/obelisk/references/delay-model.md](skills/obelisk/references/delay-model.md)

| `⌫` / `Delete` | 휴지통으로 옮기기 (10개 이상이면 먼저 물어봄) |
| `⌘Z` / `⌘⇧Z` | 실행 취소 / 다시 실행 (`Ctrl+Y`도 다시 실행) |
| `⌘↵` | 완료 (모두 완료된 작업이면 완료 취소) |
| `1` `2` `3` `4` | 우선순위 높음 · 보통 · 낮음 · 없음 |
| `T` / `P` | 오늘로 / 하루 미루기 |
| `E` / `F2` | 제목 바로 고치기 |
| `⌘D` | 복제 |
| `⌘C` / `⌘V` | 텍스트로 복사 / 줄마다 작업 하나로 붙여넣기 (빠른 추가 문법: 날짜, `#프로젝트`, `!높음`) |
| 오른쪽 클릭 | 작업 메뉴 (위 동작과 프로젝트로 옮기기, 링크 복사) |

**타임라인**: 트랙패드 핀치나 `⌘`(Windows는 `Ctrl`) + 스크롤, 또는 왼쪽 위 −/+ 버튼으로 확대합니다(확대 정도는 브라우저에 저장). 하루 폭이 300px을 넘으면 시간 눈금이 나오고, 시각이 있는 작업은 그 시각에 그려지며 15분·30분·1시간 단위로 끌 수 있습니다(시각이 없는 쪽 끝은 하루 단위). `Shift` 또는 `⌘`(Ctrl)+클릭으로 작업을 하나씩 고르고, `Shift`+빈 곳 드래그로 범위를 고릅니다. 고른 작업은 함께 끌어 옮길 수 있습니다(파급 미리보기 포함).

**여러 작업 고르기 (모든 작업 목록)**: `⌘`(Ctrl)+클릭은 하나씩 넣고 빼고, `Shift`+클릭은 마지막으로 고른 줄(또는 열려 있는 작업)부터 클릭한 줄까지 고릅니다. 고르지 않은 줄을 누른 채 끌면 지나간 줄이 모두 골라지고, 목록 바깥 빈 곳에서 끌면 사각형에 닿은 줄이 골라집니다(`⌘`·`Shift`를 누르고 끌면 더해짐). 고른 줄을 끌어 사이드바의 인박스 · 오늘 · 프로젝트에 놓으면 그리로 옮겨집니다. 아래에 뜨는 막대에서 완료 · 오늘로 · 하루 미루기 · 프로젝트 옮기기 · 우선순위 · 삭제를 한 번에 하고, `Esc`로 풉니다. 프로젝트에서 리스트↔타임라인을 바꿔도 선택이 유지되고, 다른 페이지나 공간으로 가면 풀립니다.

## 휴지통과 실행 취소

**실행 취소**: 작업을 바꾼 일(완료, 제목 · 메모 · 날짜 · 우선순위 · 프로젝트 · 담당자 변경, 추가 · 복제 · 붙여넣기, 삭제, 선행 관계 연결 · 해제)은 모두 `⌘Z`로 되돌리고 `⌘⇧Z`로 다시 합니다. 변경 뒤에 뜨는 알림의 실행 취소 버튼도 같은 기록을 씁니다. 기록은 열려 있는 탭에 최근 100개까지 남고, 공간을 바꾸거나 로그아웃하면 지워집니다. 그사이 다른 사람이 작업을 지웠으면 그 항목은 알림 없이 기록에서 빠지고, 권한이 바뀌었거나 휴지통에서 영구 삭제돼 되돌릴 수 없으면 그 이유를 알림으로 보여 주고 빠집니다. 어느 쪽이든 다음 `⌘Z`는 그 전 변경을 되돌립니다.

**휴지통**: 지운 작업은 바로 없어지지 않고 사이드바의 **휴지통**에 30일 동안 있다가 자동으로 영구 삭제됩니다(서버가 한 시간마다 정리).
- 되살리면 같은 번호(`#12`), 날짜, 상태, 활동 기록이 그대로 돌아오고, 상대 작업이 아직 있는 선행 관계도 다시 이어집니다(그사이 반대 방향 연결이 생겨 순환이 되는 연결은 빼고).
- 프로젝트가 지워졌다면 인박스로 돌아갑니다. 프로젝트를 ‘작업도 함께 삭제’로 지우면 그 작업들도 휴지통으로 가고, 되살리면 인박스에 들어갑니다. 담당자는 그 작업을 여전히 볼 수 있는 멤버일 때만 남습니다.
- 조직에서는 내가 볼 수 있는 프로젝트의 작업만 휴지통에 보입니다. 프로젝트가 없거나 지워진 작업은 만든 사람 · 담당자 · 지운 사람에게만 보입니다. 되살리기와 영구 삭제는 작업이 돌아갈 곳에 쓰기 권한이 있어야 하고, 보기 전용인 작업은 휴지통 비우기에서도 남습니다.
- 휴지통은 다른 서버로 옮기는 파일에 들어가지 않습니다. 옮기기 전에 필요한 작업은 되살려 두세요.
- AI 연결에서는 `delete_task`가 휴지통으로 옮기고, `list_trash`와 `restore_task`로 찾아서 되살립니다. REST는 `POST /api/tasks/delete`, `GET /api/trash`, `POST /api/trash/restore` · `purge` · `empty`입니다.

## 계정

- **프로필 사진**: 설정 → 일반 → 사진(내 사진), 조직 설정 → 일반 → 사진(조직 사진, 소유자·관리자만). 사진을 고르거나 끌어다 놓거나 붙여 넣으면 원 모양 편집기에서 끌어서 위치를 맞추고 슬라이더·스크롤·핀치로 확대한 뒤 저장합니다. 브라우저가 256px WebP(Safari는 PNG)로 줄여 보내고, 서버는 내용이 실제 WebP·PNG·JPEG인지와 크기(512KB, 1024px 이하)만 확인해 **DB에 저장**합니다. 그래서 따로 볼륨을 붙일 필요가 없고 매일 백업에 함께 들어갑니다. 사진 주소(`/api/avatars/<id>`)는 올릴 때마다 바뀌어 영구 캐시되고, 초대 화면에서도 보이도록 로그인 없이 열립니다. 사진이 없으면 이름의 첫 글자가 보이고, 개인 공간은 계속 Obelisk 마크를 씁니다. 계정이나 조직을 지우면 사진도 함께 지워집니다.
- **이메일**: 설정 → 일반 → 이메일에 확인 여부가 보입니다. ‘확인 메일 보내기’로 주소를 확인하고, ‘바꾸기’로 로그인 주소를 바꿉니다(비밀번호 필요, 새 주소로 보낸 링크를 열어야 바뀌고 예전 주소로 알림이 감). 둘 다 `SMTP_URL`이 있어야 합니다. 자세한 내용은 ‘서버 관리 → 메일 주소 확인’.
- **비밀번호 찾기**: 로그인 화면의 ‘비밀번호를 잊으셨나요?’에서 이메일을 적으면 60분 동안 한 번 쓸 수 있는 링크를 보냅니다(`SMTP_URL` 필요). 가입 여부와 관계없이 같은 답을 하고, 링크 토큰은 주소의 `#` 뒤에 있어 서버 로그에 남지 않으며 DB에는 해시만 저장합니다. 새 비밀번호를 정하면 그 계정의 다른 세션과 남은 링크가 모두 끝나고 이 브라우저로 로그인됩니다. 요청은 IP당 15분 10회, 주소당 시간당 3통으로 제한합니다. 메일 서버가 없는 서버에서는 운영자가 서버 관리 → 사용자에서 재설정 링크를 만들어 전해 줄 수 있습니다.
- **메일 설정**: `SMTP_URL` 하나로 SMTP 서버에 로그인해서 보냅니다(코드는 어느 SMTP든 같음). 형식은 `smtps://로그인:비밀번호@서버:465`(SSL) 또는 `smtp://로그인:비밀번호@서버:587`(STARTTLS)이고, 로그인 주소의 `@`는 그대로 써도 됩니다. 비밀번호에 `@ : / ? #`가 있으면 URL 인코딩하세요(`@` → `%40`). 받는 사람에게는 이 메일함 주소가 보이므로 개인 주소 대신 발송 전용 메일함을 하나 만드는 것을 권합니다.

  | 메일함 | `SMTP_URL` | 준비 |
  |---|---|---|
  | Gmail | `smtps://아이디@gmail.com:앱비밀번호@smtp.gmail.com:465` | Google 계정 2단계 인증을 켜고 myaccount.google.com/apppasswords에서 앱 비밀번호(16자, 공백 빼고) 발급. 하루 약 500통 |
  | 네이버 | `smtps://아이디@naver.com:앱비밀번호@smtp.naver.com:465` | 네이버 메일 → 환경설정 → POP3/IMAP 설정에서 SMTP 사용, 네이버 보안 설정에서 애플리케이션 비밀번호 발급 |
  | Proton | `smtp://주소:SMTP토큰@smtp.protonmail.ch:587` | 커스텀 도메인 주소에서만(유료 요금제). 설정 → IMAP/SMTP → SMTP tokens에서 토큰 발급 |
  | Cloudflare (내 도메인) | `smtps://api_token:API토큰@smtp.mx.cloudflare.net:465` + `MAIL_FROM=Obelisk <no-reply@내도메인>` | DNS가 Cloudflare에 있는 도메인. Workers Paid 요금제 필요(월 3,000통 포함). Compute → Email Service → Email Sending → Onboard Domain, ‘Email Sending: Edit’ 권한 API 토큰. 465 암묵적 TLS만 지원(2026년 6월 베타) |

  설정 후 `/api/auth/password-reset`이 `{"available":true}`를 돌려주고, 보내다 실패하면 백엔드 로그에 `[mail] password reset mail failed: …`가 남습니다.
- **다른 서버로 옮기기**: 설정 → 데이터 이전. 개인 공간을 파일이나 이전 링크로 다른 Obelisk 서버의 내 개인 공간에 합치고, 시간대·홈 배치·사진·Jev 같은 내 설정도 함께 옮길 수 있습니다(API 토큰은 새 서버에서 새로 만듭니다). 위 ‘다른 서버로 옮기기’ 참고.
- **계정 삭제**: 설정 → 일반 → 계정 삭제. 비밀번호를 다시 입력해야 하고 웹·iOS 세션에서만 가능합니다(API 토큰·AI 앱 불가). 개인 공간과 혼자 쓰는 조직은 함께 삭제되고, 함께 쓰는 조직에서는 나가며(만든 작업은 남고 담당자 목록에서만 빠짐, 활동 기록에 ‘계정을 삭제해 조직을 떠났습니다’), API 토큰·AI 연결·받는 웹훅·세션이 모두 사라집니다. 다른 멤버가 있는 조직의 마지막 소유자라면 먼저 다른 사람을 소유자로 지정하거나 조직을 삭제해야 합니다.
